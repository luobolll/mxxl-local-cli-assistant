# 本地 CLI 个人助手 MVP 文档

更新时间：2026-03-26

## 文档目标

这份文档只定义当前阶段的 MVP 范围、验收标准和交付边界。
具体模块结构、目录布局和数据流，以架构文档为准。

## 当前 MVP 要做什么

当前 MVP 只交付一个本地单用户 CLI 助手，必须完成以下能力：

1. 能在命令行持续接收用户输入
2. 能通过智谱 API 直接回答普通问题
3. 能通过 `add_todo` 保存待办
4. 能通过 `list_todos` 查询待办
5. 能通过 `save_memory` 保存结构化记忆
6. 能通过 `get_memory` 查询结构化记忆
7. 能把消息、待办、记忆、trace 全部落到本地 SQLite
8. 能在工具调用后返回固定模板文案
9. 能在错误场景下返回固定中文错误提示

## 当前 MVP 不做什么

当前阶段明确不做以下内容：

- MCP
- Web 页面
- HTTP API
- 多用户
- 多会话切换界面
- 多工具串联
- RAG
- 向量检索
- 多 Agent
- 邮件、浏览器自动化、Shell 执行

## 最小交付件

仓库在当前阶段至少要包含以下内容：

- 可运行的 CLI 主程序
- 完整的四个本地工具
- SQLite 初始化与 Store 层
- Prompt 组装、模型调用、决策解析、工具执行、结果格式化、trace 记录
- `.env.example`
- 最小运行说明
- 覆盖主流程和关键错误分支的自动化测试

## 完成标准

满足以下条件即可视为 MVP 落地：

1. `python -m app.cli.main` 可以启动
2. `/help`、`/clear`、`/exit` 行为正确
3. 普通问答能返回有效回答
4. 四个工具都能从主流程调用成功
5. 直接回答与工具调用都能写入 `messages`
6. 每轮请求都能写入 `traces`
7. 重启程序后待办和记忆仍然存在
8. 非法 JSON、字段缺失、未知工具、参数错误、工具异常都有固定错误提示
9. 项目不引入架构文档范围外的新能力

## 验收建议

建议按以下顺序验收：

1. 跑自动化测试，确认基础行为稳定
2. 用真实智谱配置启动 CLI
3. 人工执行一轮普通问答
4. 人工执行一轮待办保存和查询
5. 人工执行一轮记忆保存和查询
6. 查看 `data/agent.db`，确认四张表都有正确写入

## 后续阶段入口

只有在本 MVP 验收通过后，才进入下一阶段。
下一阶段优先顺序保持与架构文档一致：

1. 会话管理完善
2. 更细的记忆策略
3. 更多本地低风险工具
